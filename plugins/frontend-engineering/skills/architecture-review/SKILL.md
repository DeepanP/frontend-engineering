# Architecture Review

Review:
- module/component boundaries
- state ownership
- data flow
- API boundaries
- dependency direction
- reuse
- testability

Prefer simple, reversible decisions.
Avoid abstractions for hypothetical needs.

Output current state, proposed approach, affected modules, tradeoffs, risks and testing strategy.
